# shelf

> **Not everything deserves a note.**

Временная полка для того, что ты пока не хочешь потерять.

`shelf` — это локальный CLI, который сохраняет информацию в момент, когда ты
на неё наткнулся, не заставляя заранее решать, что это такое.

```bash
shelf add "git worktree add ../foo feature/foo"
```

Без заголовка. Без папки. Без тегов. Без вопроса «куда это вообще положить?»
Потом разберёшься.

---

## Проблема

Есть целый класс информации, который все инструменты обрабатывают плохо:

```bash
echo "shit I need to remember" >> ~/tmp.txt
```

Ты хочешь её сохранить, но не хочешь пока решать, _что_ это. Не закладка, не
задача, не заметка, не файл.

Любой существующий инструмент заставляет принять решение **до** сохранения:

| Инструмент     | Хорошо решает                 | Ломается, когда                       |
| -------------- | ----------------------------- | ------------------------------------- |
| clipboard      | мгновенный capture            | информация исчезает завтра            |
| `/tmp`         | действительно временные файлы | нет UX, нет поиска                    |
| `~/notes`      | простое persistent-хранилище  | организовывать всё придётся самому    |
| shell history  | команды                       | только shell-команды                  |
| закладки       | ссылки                        | только ссылки                         |
| Obsidian       | долговременные знания         | слишком много обязательств для мусора |
| Saved Messages | невероятно быстрый capture    | превращается в помойку                |

`shelf` занимает промежуточную стадию: **сначала capture, потом решение.**

## Три свойства

```
CAPTURE          shelf add "..."
                 никаких решений

CONTEXT          cwd, git-репозиторий, ветка, hostname, timestamp
                 собирается автоматически, руками не вводится

LIFECYCLE        keep / expire / delete / promote
                 полка — это буфер, а не архив
```

### Capture без решений

Команда должна быть настолько дешёвой, чтобы ты перестал спрашивать себя
«куда мне это записать?». Остаётся ровно один вопрос: **что я сохраняю?**

### Автоматический контекст

```bash
cd ~/projects/mes
git checkout feature/fib
shelf add "this crashes after 13000 routes"
```

Через месяц `shelf search "13000"` вернёт тебе директорию, репозиторий и
ветку, из которых это наблюдение появилось. Контекст — это метаданные, он
никогда не попадает в твой текст.

Именно этого не может дать обычный `~/notes.txt`. И именно это делает `shelf`
полезным для debugging, сисадминства и исследований, а не просто «заметками».

### Сборка мусора

Notes-приложения оптимизированы под _сохраняй всё_. `shelf` оптимизирован под
_сохраняй всё, оставляй только выжившее_.

Предметы с TTL не удаляются в момент истечения — они переходят в `expired` и
ждут твоего решения:

```bash
shelf clean

Expired items:

8 days old   temporary nginx config
11 days old  check this command
17 days old  TODO: investigate...

Delete these items? [y/N]
```

Так полка остаётся маленькой, а «я сохранил это временно» не превращается в
кладбище из 847 TODO.

## Установка

```bash
git clone --recursive git@github.com:leonyaognev/shelf.git
cd shelf
make release
sudo install -m755 shelf /usr/local/bin/shelf
```

Логгер лежит в git-сабмодуле, поэтому `--recursive` важен.

## Использование

```
shelf add "..."          сохранить предмет
shelf add -              сохранить из stdin
shelf add <file>         сохранить файл
shelf edit               открыть $EDITOR для нового предмета
shelf list               список предметов
shelf show <id>          показать один предмет
shelf search <query>     поиск
shelf delete <id>        удалить предмет
shelf today              всё, что сохранено сегодня

shelf add --ttl 2d "..."     протухнуть через 2 дня
shelf export --markdown      выгрузить всё в Markdown
```

Всё — обычный текст, который ищется через `grep`:

```bash
cat config.yaml | shelf add -
shelf search "nginx" | awk '{print $1}' | xargs shelf delete
```

### Формат предмета

```markdown
# 1842

Working directory:
~/projects/mes

Git branch:
feature/fib

Content:

```

## Чем shelf НЕ является

Это самая важная часть.

`shelf` — это **не**:

- notes-приложение, не замена Obsidian, Joplin, Evernote или Notion
- личная wiki или база знаний
- таск-менеджер, менеджер закладок или менеджер паролей
- файловый менеджер, менеджер буфера обмена или фронтенд для git
- AI-граф знаний

И он никогда не будет требовать сервер, аккаунт, облако, интернет или систему
плагинов.

Если `shelf` дорастёт до чего-то из этого, он провалил задачу, ради которой
создавался.

## Roadmap

**MVP** — доказать, что `shelf add` становится привычкой:

- локальное persistent-хранилище (`id`, `content`, `created_at`, `updated_at`)
- `add` / `list` / `show` / `edit` / `delete`
- `add -` для stdin, `add <file>` для файлов
- автоматический контекст: cwd, hostname, git-репозиторий и ветка
- опциональный `--ttl` плюс `shelf clean`
- `shelf export --markdown`

**Дальше** — только если core уже хорош без этого:

- TUI для просмотра и массовых операций
- `shelf promote` — превратить выжившие предметы в структурированный документ
- интеграция с буфером обмена / shell hook
- поиск по метаданным и проекту
- группировка и дедупликация через LLM как _отдельный_ инструмент поверх
  выгруженного Markdown — никогда как зависимость core

**Явно не планируется:** sync, cloud, аккаунты, плагины, daemon,
распределённое хранилище, мобильное приложение, web UI.

## Сборка

```
make            собрать shelf + документацию
make release    оптимизированная сборка
make debug      -O0 -g
make test       собрать и прогнать тесты
make coverage   HTML-отчёт lcov
make valgrind   проверка на утечки
make clean
```

Makefile находит все `src/**/*.cpp`, кроме `src/vendor/`, так что новые
исходники подхватываются автоматически.

Нужны `g++` (C++20), `make`, `doxygen`. Для `make test` дополнительно нужен
`gtest`, для `make coverage` — `lcov`/`genhtml`.

## Дизайн

Ядро намеренно простое: filesystem, сериализация, запуск процессов, `$EDITOR`,
stdin/stdout. Никакой изощрённости.

Хранилище лежит в `~/.local/share/shelf/` и использует собственный формат
файлов, а не SQLite. Каждый предмет — отдельный файл, поэтому удаление это
`unlink()`, а редактирование — атомарная замена. Файловая система _и есть_
движок хранения.

```
~/.local/share/shelf/
└── items/
    ├── 00001841
    └── 00001842
```

Формат со временем получит байт версии, а предмет, который не удалось
прочитать, должен пропускаться, а не ронять программу. Так всё остаётся
извлекаемым руками: `cp -a ~/.local/share/shelf ~/backup/` — и полка переехала.

> Твои данные никогда не должны требовать бинарник, чтобы их достать. Если
> это перестало быть правдой, формат стал слишком хитрым.

Если ты когда-нибудь начнёшь проектировать интерфейс плагинов, сервисный слой,
query planner или протокол синхронизации — ты вышел за рамки проекта.

```bash
git submodule update --init --recursive
make debug
```
